## 实施取舍

现有项目为 Express + TypeScript + 原生 HTML/JS + MySQL。Dashboard 为 Python/Streamlit，FreqUI 为 Vue。直接替换整站将连带重写登录、通知和数据库接口。因此本次复用现有推荐与历史 API，并按参考项目的交互模式实现研究界面。

没有复制上游源码或静态资源。Dashboard README 声明 Apache-2.0，FreqUI LICENSE 为 GPL-3.0；后续如引入源码应单独记录来源和许可证。本次不增加交易引擎依赖。

## 已实现

1. 推荐研究台：按股票、月/季/年、建议、风险状态、最低分筛选，按评分、波动、代码排序。
2. 当前浏览器按账户保存筛选。筛选仅作用于 API 已返回的榜单，不声称扫描全市场。
3. 同一股票不同周期可独立选择，最多三条横向对比。展示推荐依据、风险、波动、区间回撤和因子贡献。
4. 复盘按股票、周期、人工结论筛选。显示样本量、人工准确率、平均录入收益及分周期结果。
5. 成本情景：对每条有效收益扣除指定基点，展示敏感性，不修改原始记录。
6. CSV 导出当前筛选的历史，包含快照批次和复盘原因，并防止表格公式注入。
7. 修复筛选后保存复盘的行定位：始终使用原始历史中的索引，避免保存到别的股票。
8. 推荐页优先读取数据库最新快照，显示生成日期和超过 24 小时的提示；避免每次进入页面都等待外部行情。主动生成仍使用原有推荐引擎。

## 统计口径

- 风险状态是固定规则的研究提示，不是信用评级。缺失数据不填零，不表示低风险。
- 重点核验：年化波动率至少 55%，或距区间高点回撤至少 30%；常规核验阈值分别为 30%、15%。任一已知指标触发重点核验时保留该提示，即使另一个指标缺失。
- 准确率 = 人工标记准确的条数 / 已复盘条数，部分准确单独展示。
- 待复盘及空收益不参与平均收益，零收益参与；统计为算术平均，不是资产净值曲线、年化收益或组合回测。
- 额外成本按 100 基点 = 1 个百分点扣减。如果已录入收益本身是净收益，这一项表示额外压力情景，避免称其为真实净利润。
- 每次最多载入最近 500 条推荐记录，页面显示样本范围。记录之间可能相关，不能把样本条数视为独立实验数。
- 页面显示快照生成时间，不是行情采集时间。现有 API 尚未为每项指标提供来源日期。

## 下一步优先级

最需要补齐的是带日期、来源和证据的真实研究数据。优先为价格、财务、负责人信息、政策事件记录来源与时效，再做基准超额收益、到期自动复盘和因子归因。没有基准、完整价格路径和持仓定义前，不展示夏普率、组合最大回撤或自动胜率。

当前升级不改数据库结构，沿用已有 MySQL 推荐快照及复盘表；后续数据库改动仍统一放在 `sql/`。
